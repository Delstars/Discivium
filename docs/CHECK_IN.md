# Check-in preparation

Use this checklist to organize the team's own work and confirm the instructor's expectations. It is not completed analysis.

- [ ] Confirm team registration and topic approval.
- [ ] Confirm the exact check-in date/time and presentation slot.
- [ ] State the problem, stakeholders, supporting observations and project boundary.
- [ ] Separate functional requirements, measurable quality scenarios and constraints.
- [ ] Agree the first-release use cases and acceptance criteria.
- [ ] Prepare a use case diagram and descriptions.
- [ ] Prepare an activity diagram for a significant workflow.
- [ ] Prepare a system sequence diagram with the whole system as a single black box.
- [ ] Prepare a state machine where appropriate, or explain why none is needed.
- [ ] Prepare the class/domain work requested for the checkpoint.
- [ ] Check that actors, operations, states and entity names agree across models.
- [ ] Give each near-term task one owner, a reviewer and dependencies.

Retain editable diagram sources and export readable PDFs for course submission using an appropriate UML tool. The final project brief explicitly requires component and deployment diagrams as well as the other named diagrams; keep a complete deliverables checklist as the report develops.
